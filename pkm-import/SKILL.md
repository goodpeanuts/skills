# PKM 文献笔记导入

本 skill 的 API v2 负责来源扫描、标题清洗、特征注释、正文变换、台账和恢复。目标库的规则仍由库自身决定：每次现场读取适用的根/区域规则、引用模板和有限存量样本，据此确定本次参数，不缓存库规范。

## GUI 发起的 DSH 会话

提示词提供已绑定本会话的 `requestId`。使用专用工具 `pkm_import`，不另起会话，不读完整台账，不自行重写请求、脚本或库规则。

1. **inspect**：确认 CLI 指向的库名与所选路径一致，读取现场规则、模板列表、有限样本和所选来源的台账。需要引用规则或模板正文时，再以 `readPaths` 传库内相对路径；必须实际读取适用模板。
2. **plan**：提供现场确定的 `parameters`：
   - `template`：Obsidian 模板列表中的实际模板名，不是模板路径。
   - `template_path`：契约登记的库内模板路径，必须与模板名对应。
   - `attachments_folder`、`attachment_naming`（`{md5}` 为摘要，`{ext}` 已含前导点，例如 `.png`；组合写 `{md5}{ext}`，不重复加点）、`embed`（支持 `{path}`）：来自本次附件规约；没有成文规则时采用有限样本的实际写法。
   - `create_interval`：来自库对逐篇模板创建、身份唯一性和节奏的要求。
   - `tags`：用户本次指定值，默认 `literature`；与库规则冲突时停止报告。
   - `identity_exempt_paths`：只使用现场库规则明确登记的身份检查例外，不自行增加。
   多个所选区域的规则不兼容时先报告并拆分请求，不能用一套参数静默覆盖差异。
   用简短表格说明参数依据。计划返回 `planRevision`、精确笔记与附件清单和状态汇总；只写本请求的私有计划，不登记 profile、不改台账或目标库。
3. **到此停下**：展示新建、更新、仅记账、跳过和错误，等待用户在本会话明确确认执行。页面点击「导入」只是发起会话，不是提前写入授权。
4. **apply**：传原 `requestId`、`planRevision` 和 `confirmed=true`，不再覆盖参数。专用工具在目标库写入前按 DSH 实际沙箱策略取得本次单次审批；拒绝、取消或服务不可用时不写入。模板和规则变化要求重新计划并确认；源总结变化或缺失时回到页面刷新并重新发起。
5. **verify**：仅核验本次请求，报告每个单元的成功、跳过、失败和未检查项；不将局部检查表述为全库合规。提醒提交内容仓库中的台账，不自动 git commit。

在会话里简短反馈检查、待确认、导入、恢复及核验阶段。无需向用户重复整份机器 profile、哈希或全库历史。

## 库操作与身份

- 所有目标库的规则、模板、正文、附件读写都经 `obsidian` CLI；允许通过其 `eval` 调用 Obsidian Vault API。使用固定操作与编码数据，不把来源正文拼成 JavaScript 指令。
- 内容采用 ASCII 分块传输，长度及摘要校验后单次写入，完整回读；保留中文、表情、代码块及字面量 `\n`、`\t`。CLI 不可用或能力不足时停止，不退回文件系统写入。
- 新笔记真实执行库模板；`up`、`createdTime` 等身份字段来自模板，不能手工拼值、回填或因重试重新生成。更新保留整个原 frontmatter，只有本次计划中的标签允许合并。
- 特征注释 `<!-- pkm-import: source-id=平台/ID[/pNN] -->` 放在 frontmatter 后正文首行。只认特征，不全文搜索 BV 号来认领笔记。
- 同步总结正文时保留原生 callout 的类型、标题、引用层级与 `+`／`-` 展开状态，不重新生成 Q/A 标签或合并不同用途的卡片。附件映射不能破坏块结构；回读比较完整正文，并按现场库规则检查实际显示。保留笔记中已有、且本次新版源文档尚未包含的合法格式修复；发现额外手写内容或未知差异时先核对，不直接覆盖。
- `conflict`（同名无特征）不触碰；`missing` 默认只报告。GUI 不在原请求中扩大为重建任务，另有明确重建要求时重新制定请求。
- 改导入目录只影响新笔记，既有笔记保留台账位置。多 P 课程使用课程文件夹和各讲笔记，不建 MOC。

## 中断与恢复

先调用 `status` 查询实际状态，不盲目重放写入。恢复日志记录本请求的创建凭据、模板身份、内容指纹、附件和台账阶段。

- 已完成项核验后跳过，不重复创建或重复记账。
- 只有能证明属于本请求且未被修改的半成品才可续跑，保留第一次真实模板身份。 对已记录精确指纹、尚未写正文且仅含 frontmatter 的模板骨架，仅容许 `createdTime` 同一时间值的引号序列化和末尾换行变化；保留首次模板身份，不放宽其他字段、正文或已写入内容的修改检查。
- 正文完成但台账未提交时，完整核验后补记一次。
- 模板创建超时、未取得创建凭据、用户改动或其他归属不确定情况，停止并报告具体路径，不覆盖、不自动重建或删除。
- 不永久删除笔记，不自动清理可能共享的附件。原计划未失效时续跑沿用已有执行确认，权限仍按本次工具调用审批。

## 独立 CLI

入口 `scripts/pkm_import.py`，需要 Python 3.9+、正在运行的 Obsidian 及已启用的 CLI。运行路径均由当前安装位置、工作区和用户选择解析。

- `capabilities`：返回 API 版本、支持操作和库 I/O 能力。
- `inspect --repo R --vault-path V --vault-name N --notes-folder F --json P`：创建本次请求并现场检查；不改台账或库。已有唯一 profile 时可沿用定位信息。
- `plan`：同上定位参数，另提供 `--parameters 参数文件`；读取本次库规范确定参数后生成带版本的计划。
- `apply --plan P --plan-revision REV`：仅在用户确认该版本计划后运行。独立 CLI 的调用者负责具备本次目标路径的操作权限。
- `verify --plan P --plan-revision REV`、`status --plan P`：当前请求核验及恢复查询。
- `verify --all --ledger L`：只有用户明确要求历史巡检时使用，不作为 GUI 默认验收。
- `request --request 请求文件 --action inspect|plan|apply|verify|status`：程序化入口，参数 JSON 从 stdin 读取；不要手改冻结请求绕过范围与来源校验。

台账固定在内容仓库的 `pkm-import/ledger.json`，保留现有 profile 和导入历史结构，逐单元原子写入。GUI 请求与恢复状态保存在宿主私有持久目录，不写库内临时校验程序。
