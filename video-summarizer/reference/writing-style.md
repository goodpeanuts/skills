# 中文行文风格基线（video-summarizer 版）

本文件与 `summary-prompt.md` 的「严格规则 1–15」**并行生效**，专注于**句子级行文习惯**。严格规则管"写什么/不写什么"，本文件管"怎么写"。

来源：`blader/humanizer`（58.2k⭐，基于维基百科 "Signs of AI writing"）+ `larashero3-dotcom/lieflat-less-ai-tone`（282 万字语料统计）+ `KKKKhazix/human-writing`（禁动作理念）。

> **哲学**：单次命中一个弱信号不算 AI 味，但同段三处并现就是 AI 味；多个强信号哪怕散落全文也算 AI 味。允许保留作者个性的细节：具体不寻常的细节、未解的矛盾情绪、真实插话、第一人称自我修正——这些是人味的来源。

## 强信号（单次命中即改，§1–§7）

强信号单次出现就必须改写，无需其他佐证。

### §1 破折号零容忍

正文行内禁止 `——`。需要用句号、逗号、冒号（仅命名标识后）、括号替代。

```
错：门槛卡死大多数新人——注册180天、1000粉、30篇作品
对：门槛卡死大多数新人。注册180天、1000粉、30篇作品
对：门槛卡死大多数新人（注册180天、1000粉、30篇作品）
```

**例外**：`evidence/` 底稿、引用原文、literal 代码块不受此约束；TL;DR「只看 N 分钟」行尾对时间范围的解释可用「——」衔接（因为那是导航注释而非正文行文）。

### §2 冒号纪律

正文行内冒号只允许两处：**命名标识后引述**（`标题：xxx`、`理由：…`、`条件：…`）与**小结后的展开**（一段落一句话末尾用冒号引出下文，但一段至多一次）。**禁止**用冒号做主从展开（"X：加一长段"），主从关系用句号切分或改写为从句。

```
错：开店只有两条路：正式店铺、个人售卖，每条各有门槛
对：开店只有两条路。正式店铺、个人售卖各有门槛
```

### §3 "不是 A 而是 B"

该句式单次出现即改，不要"不是…而是…"的对举结构。

```
错：这不是一个新发明，而是对旧做法的重新组合
对：这是对旧做法的重新组合（并非新发明）
对：这本质上是对旧做法的重新组合
```

### §4 段首零回指评论（最高区分度，R=4.4）

每段开头禁止无回指的评论性短语——`值得注意` `不难发现` `可以看出` `这意味着` `换句话说` `由此可见` `说到底` `本质上` `归根结底`。要么删掉直接说事，要么加"这/该/此/UP 主"等明确回指。

```
错段首：值得注意的是，平台已开始清理
对段首：平台已开始清理
对段首：这个动作值得注意，因为它意味着…
```

### §5 拔高拔意义

禁用：`深刻地` `具有重要的` `深远的` `里程碑` `划时代` `极富` `淋漓尽致` `彰显` `体现了` `赋能` `助力` `打造` `闭环` `大幅度提升` `完美契合`。

```
错：这个工作流完美契合了 AI 时代的需求
对：这个工作流解决了…（具体解决了什么）
```

### §6 假装对抗（"我不是说…"、"to be clear"式）

不要回应无人提出的反对；多处连续反驳信号更强。

```
错：我不是说你必须买最贵的，但至少几十块是要花的
对：几十块是要花的
```

### §7 导览式开场与铺垫

禁：`让我们` `接下来` `一起` `说实话` `你可能会问` `先说结论`（除非是 TL;DR 章节内）。

```
错：让我们看看 UP 主怎么做的
对：UP 主的做法：
```

## 弱信号（需同段并现才改，§8–§11）

这些单次出现不算问题——人也会用。但同段三处并现就该改一段。

### §8 排比三连

连续三个结构相同的短句，例如"没有门槛，没有流水，没有压力"。

### §9 重复句首

同段相邻 ≥3 句用同一主语开头，如"UP 主说… UP 主说… UP 主说…"。

### §10 被动无主语

"被认为/被称/据悉"缺主语。

### §11 抽象名词堆叠

一句内连续 3 个抽象名词（"机制的有效性"），优先换成动词表达。

## 禁动作（不区分句式，查行为意图，§12–§14）

这些不是"句式"，是"写作动作"——句式可以千变万化，行为都是 AI 味。

### §12 先立误解再推翻

禁止"你以为 X 其实 Y""很多人以为 X 实际 Y"的动作。要么直接陈述事实，要么把误解作为背景如实交代（"网上普遍认为 X，但 UP 主的解法是 Y"——这种是对背景的引用，合法）。

### §13 每段必需

每段至少带一件"新东西"：**新事实 / 新动作 / 新例子 / 新后果**。写段之前问自己：这段如果删掉，读者会失去什么？答不上来就删。

### §14 结论不许 placeholder

TL;DR、章节收尾禁止`未来可期` `拭目以待` `值得期待` `前景广阔` `总而言之` `综上所述`这类 placeholder 收尾。收尾要么是一个具体记忆点，要么是一个行动钩子（见 anti-defensive-writing-Skill 的"发布会开场思维"）。

## 保留例外

以下不受上面任何规则约束：

1. **直接引语**（`>`引用块 / 「引用」）——保持原话。
2. **专有名词与型号**——按字幕逐字转写（严格规则 10 已有）。
3. **作者个性细节**——具体数字、原话措辞、有真实冲突的自我修正不删，这是人味的来源。
4. **`evidence/` 底稿**——底稿是工作文档，不参与本基线。
5. **literal code 块**——代码、命令、路径原样保留。

## 自检清单（写完照一遍）

```
□ 数字数：summary 里 "——" 出现几次？目标 ≤1（顶行时间和"只看 N 分钟"除外）
□ 数字数：正文行内 ":" 出现几次？目标 <字幕长度/2000
□ 各段首看一眼：有"值得注意/这意味着/本质上是"开段吗？
□ 各段读一遍：有"不是…而是…"对举吗？
□ 收尾看一句：是 placeholder 还是具体钩子？
```
