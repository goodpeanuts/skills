# 场景配方

每条给出：**尺寸 → 画面结构 → 文案容量 → 常见翻车**。
用户只说"做张图"时，先问清楚发到哪，再按下表定尺寸。

---

## 1. 头像 / 品牌标记
**尺寸** `avatar` 1024×1024
**结构**：底色满铺 → 中心一个几何形（圆/方/多边形）→ 形内一个字符或符号 → 噪点层。
**文案**：1 个汉字，或 1–2 个字母。绝不放词组。
**要点**：会被裁圆，主体压进中心 80% 的圆里；缩到 48px 还要能认出来——先把画板缩到 5% 看一眼。
**翻车**：放全名、放 slogan、四角有装饰被裁掉。

## 2. 公众号头条封面
**尺寸** `wechat` 900×383
**结构**：左侧一条色带 → 眉标（栏目/期号，等宽小字）→ 主标题 2 行 → 底部落款 + 日期。
**文案**：主标题 ≤ 16 字，拆成 2 行；眉标 ≤ 12 字符。
**要点**：列表页会裁成正方形取中间——**主标题必须落在水平中段**。关键词染强调色。
**翻车**：标题 3 行以上；重要信息贴左右边缘（被裁）。

## 3. OG 分享图 / 链接预览
**尺寸** `og` 1200×630
**结构**：品牌标记（小，左上或左下）→ 标题（大，压左，最多 3 行）→ 一句副标 → 域名/作者。
**文案**：标题 ≤ 24 字，副标 ≤ 30 字。
**要点**：微信/Slack/飞书裁切不一，**四边留 8% 不放东西**。在 IM 里只有 ~300px 宽，标题字号 ≥ 64px。
**翻车**：把整篇摘要塞进去；用截图当背景导致字看不清。

## 4. 横幅 Banner / 网站 Hero
**尺寸** `banner` 1500×600（X 主页头图用 `x-header` 1500×500）
**结构**：左 2/3 文字（标题 + 一句话）+ 右 1/3 一个重量元素（徽章/图形/大数字）。
**文案**：标题 ≤ 12 字或一句英文短句；副标 ≤ 40 字。
**要点**：X 头图**左下角 200×200 被头像盖住**，右下角有按钮，别放字。移动端会裁成 16:9。
**翻车**：文字铺满整宽，缩小后一片糊。

## 5. 小红书封面
**尺寸** `xhs` 1080×1440
**结构**：顶部胶囊标签（略旋转）→ 超大标题 3 行（占画板高 35%+）→ 中间留白 → 底部编号清单 3–5 条 → 落款 @账号。
**文案**：标题每行 4–6 字；清单每条 ≤ 14 字。
**要点**：**底部 18% 会被平台标题栏盖住**，落款要往上收。高饱和底色（黄/橙/蓝绿）+ 纯黑字最抓眼。
**翻车**：标题不够大（这是小红书封面的头号问题）；清单超过 5 条；用浅灰字。

## 6. 知识卡片 / 干货清单
**尺寸** `square` 1080×1080 或 `xhs` 1080×1440
**结构**：眉标 → 主问题/主张 → 3–5 条编号要点（编号用等宽字、弱化）→ 落款。
**文案**：每条要点 ≤ 18 字，动词开头。
**要点**：编号列用 `--mono` 且 `opacity:.45`，让内容突出。多张成组时保持同一模板只换内容。
**翻车**：一张塞 8 条；要点写成完整段落。

## 7. 金句卡 / 引用
**尺寸** `square` 1080×1080
**结构**：一个大引号（超大、低透明度、可出血）→ 引文（衬线、大）→ 一条短横线 → 出处。
**文案**：引文 ≤ 40 字。
**要点**：引文本身就是构图，别再加装饰。衬线字体 + 暖纸主题最稳。
**翻车**：引文太长导致字号被迫变小。

## 8. 代码片段图
**尺寸** `og` 1200×630（短片段）或 `square`（竖排片段）
**结构**：窗口条（三个圆点或文件名，别都做）→ 代码块（等宽、行高 1.65）→ 可选行号（弱化）。
**文案**：**≤ 16 行、每行 ≤ 60 字符**。超了就截取核心几行。
**要点**：语法高亮手写成 `<span>`，配色取自主题（终端主题最合适）。高亮 1–2 行用背景色带 + 左侧标记。
**翻车**：贴一整个文件；字号太小；用截图（发糊）。

## 9. 数据卡 / 指标图
**尺寸** `og` 1200×630 或 `square`
**结构**：标题 → 1 个主数字（巨大，占高 30%+）→ 变化量（带方向色）→ 2–3 个次要指标一行 → 数据来源和时间。
**文案**：主数字 ≤ 6 字符；标签 ≤ 8 字。
**要点**：数字用 `font-variant-numeric:tabular-nums`。涨跌用色**必须**配符号（↑↓），不能只靠红绿。
**翻车**：四个数字一样大；没写口径和时间。

## 10. 功能发布 / Changelog 图
**尺寸** `og` 1200×630
**结构**：版本号角标 → 功能名（大）→ 一句话价值 → 3 个要点或一个简化界面示意 → 日期。
**文案**：功能名 ≤ 10 字；价值句 ≤ 25 字，讲结果不讲实现。
**要点**：极简产品主题（H）或瑞士（D）。界面示意用纯 CSS 画方块和线条，不要贴真截图。
**翻车**：写成更新日志全文。

## 11. 对比图 Before / After
**尺寸** `og` 1200×630 或 `square`
**结构**：左右两栏等宽 → 中间一条分隔线 + 一个箭头/"→" → 每栏顶部一个标签（旧/新）。
**文案**：每栏 ≤ 4 行。
**要点**：两栏视觉重量要**不对等**——旧的降饱和/灰化，新的用强调色。否则读者不知道该看哪边。
**翻车**：两边一模一样的样式；用红绿表示好坏（色盲不友好）。

## 12. 步骤图 / 流程
**尺寸** `xhs` 1080×1440（竖排）或 `slide` 1920×1080（横排）
**结构**：标题 → 3–5 个步骤，每步：大编号 + 短标题 + 一句说明 → 步骤间用细线或箭头连。
**文案**：步骤标题 ≤ 8 字，说明 ≤ 20 字。
**要点**：编号是视觉主角，用巨大的数字（低透明度或描边）。步骤数 ≤ 5。
**翻车**：画成流程图软件那种圆角框 + 箭头，毫无个性。

## 13. 视频封面 / 缩略图
**尺寸** `thumb` 1280×720（B站用 `bili` 1146×717）
**结构**：一句钩子（超大，2 行内）+ 一个强对比色块/描边让字从背景里跳出来。
**文案**：≤ 12 字。
**要点**：会被缩到 **210px 宽**——先把画板缩到 16% 看一眼能不能读。文字加粗描边或实底色块。
**翻车**：字太小；低对比；四角放信息（会被时长角标盖）。

## 14. 幻灯片单页
**尺寸** `slide` 1920×1080
**结构**：左上标题 → 正文区（要点或一张图示）→ 右下页码/品牌。
**文案**：一页一个观点，正文 ≤ 5 行，字号 ≥ 28px。
**要点**：同一套里所有页共用同一个网格和边距。
**翻车**：一页讲三件事。

## 15. 活动海报
**尺寸** `story` 1080×1920 或 `a4` 2480×3508（要打印）
**结构**：主视觉（大字/图形，占上 60%）→ 活动名 → 时间地点（等宽、成组）→ 主办方/二维码位。
**文案**：活动名 ≤ 12 字。
**要点**：时间地点这类信息**成组对齐**，别散开。打印稿四周留 3mm 出血。
**翻车**：信息平均分布，没有主视觉。

## 16. 名片 / 个人介绍图
**尺寸** `card` 1063×638（印刷）或 `og`（线上）
**结构**：姓名（大）→ 头衔（小）→ 分隔线 → 联系方式成列 → 一个标记。
**要点**：联系方式用等宽字对齐；线上版可以放二维码占位方块。

## 17. 多图拼版 / 作品集合集
**尺寸** 由拼版脚本按输入图自动算出
**用途**：把一组图拼成一张总览——作品集九宫格、系列图合集、风格对比、前后对照墙。
```bash
node $SKILL/scripts/contact.mjs out/png/*.png --cols 5 --label
```
**要点**：**不要用 CSS 的 `column-count` 做瀑布流**——它的列平衡算法会在底部留下大块空洞，
一眼就看出是没排好。脚本用的是 justified 打包：先按高度降序贪心塞进当前最矮的列，
再反解每列宽度使所有列**高度完全相等**（列宽差异通常只有几个百分点，肉眼看不出，但底部严丝合缝）。
**翻车**：图片数量和列数不匹配（少于 2×列数时会很难看）；混入尺寸悬殊的图（超宽横图会把一列压得很扁）。

---

## 通用工作法

1. **先问发到哪**，再定尺寸。不确定就同时出 `og` + `square` 两版。
2. **文案先于排版**。把字数压到上表的额度内，排版会自己变好看。
3. **成组的图共用一套变量**：改 `:root` 的 4 个色值就能换主题，别每张图重写样式。
4. **出图前缩到 15% 看一眼**——信息流里就是这个尺寸。读不出主标题就重来。
